# 无损迁移验收清单

## A. 静态正确性

- [ ] 聚宽原文件未被覆盖。
- [ ] QMT 文件首行声明 GBK，实际内容可编码为 GBK。
- [ ] 通过 Python 3.6 语法检查。
- [ ] 不再引用 `jqdata/jqdatasdk/jqfactor` 或未实现的聚宽全局 API。
- [ ] 所有证券代码、品种、周期和单位已核对。
- [ ] 所有策略主动日志均包含 QMT `C.title` 解析出的策略名和触发输出的 K 线时间，格式为 `[策略名=...] [K线时间=...] [LEVEL] ...`；业务函数无直接 `print/logging/log.*`。
- [ ] 使用 `get_instrument_detail(...)[InstrumentName]` 主路径解析名称，无“未知名称”静默回退。
- [ ] 静态合约元数据与交易日动态字段分开缓存；`UpStopPrice`、`DownStopPrice` 不跨交易日复用，LIVE 买入计算数量和最终报单前均强制刷新当日详情。
- [ ] `000001.SZ` 可解析为“平安银行”，策略股票池、持仓、委托和成交标的名称均非空。
- [ ] 所有 QMT 下单枚举均有官方文档依据。
- [ ] 聚宽默认市价订单未被迁移成 `prType=5` 最新价限价；普通沪深股票/ETF 分别使用已核对的 `.SH=42`、`.SZ=47` 市价类型及 `price=0` 保护价。

## B. 时序与数据

- [ ] 初始化、开盘前、盘中、收盘后和日/周/月任务的执行次数一致。
- [ ] 当前 bar 与上一已完成 bar 的边界一致。
- [ ] 相同交易日历、时区和时间窗口。
- [ ] 复权、停牌填充、缺失值、上市/退市过滤一致。
- [ ] 财务数据按公告可知日取值，无未来数据。
- [ ] 行业、概念和指数成分使用相同历史时点。
- [ ] QMT 所需本地基础周期、财务和特色数据已下载。
- [ ] 所有 `get_market_data_ex` 调用显式决定 `subscribe`；历史请求为 `False`，没有使用 LIVE 全局开关机械订阅全市场历史数据。
- [ ] 当前快照优先使用 `get_full_tick`；连续分钟订阅只覆盖受控候选池，记录订阅成功/失败，并在换池和停止时释放订阅号。
- [ ] 临时停牌检测至少取得 N 根当前交易日真实分钟线；空表、数量不足、订阅失败和时间异常均为 `DATA_UNAVAILABLE`，不会误报停牌。
- [ ] LIVE 不仅检查 `is_last_bar` 和 bar 日期=本机日期，还固定使用 `abs((runtime - bar_time).total_seconds()) <= 180`；`-180/+180` 秒边界通过，任一方向超出 180 秒均不进入 routine 或下单。
- [ ] LIVE 日历空值、异常、接口缺失和过期数据均为 `UNAVAILABLE`；只缓存确认交易日的 True，`NON_TRADING/UNAVAILABLE` 均失败关闭但后续重试，并要求客户端已下载节假日数据。
- [ ] LIVE 与 BACKTEST 都按 `context.current_dt` 的 K 线时间和源策略顺序运行到期任务；没有墙钟调度、`live_target_time`、精确分钟或 `LIVE补运行` 特殊分支。
- [ ] `g.executed_routines` 在 K 线日期变化时清空；未到时不提前、当日不重复。已披露进程重启会丢失集合，交易型任务同时检查最新持仓、账户、在途委托、目标差额和订单唯一键。
- [ ] `get_bar_timetag` 为 0/空/无效时日志显示“无可用K线”，不会出现 1970 年时间。

## C. 交易

- [ ] 账户现金、总资产、持仓总量和可卖量字段定义一致。
- [ ] 目标数量/市值转换保持原意，取整规则明确。
- [ ] T+1、涨跌停、价格笼子、停牌和最小委托量已处理。
- [ ] 手续费、印花税、过户费、滑点和成交量限制一致。
- [ ] 委托异步、部分成交、撤单和重复信号已处理。
- [ ] `quickTrade` 与调用场景匹配，历史回放不会发实盘单。
- [ ] `passorder` 的 `userOrderId` 小于 24 字符且可在 `m_strRemark` 中关联委托和成交；日志不会把 API 调用完成误写成成交成功。
- [ ] `price=0` 市价买入按当日 `UpStopPrice`、最新可用资金和费用预留资金；报单前保护价变化会重新缩量，无法刷新保护价时失败关闭。
- [ ] 零成交资金不足废单会记录真实状态和原因、清除动态详情缓存、释放信号键；重试时重新定价/验资/定量并至少减少一个最小交易单位。
- [ ] LIVE 从 `get_full_tick` 记录 `latest_reference_price`，逐笔记录成交价/数量，并输出成交量加权 `final_deal_price` 及买卖方向一致的绝对/比例/bps 滑点。
- [ ] 重复成交回调不会重复累计；部分成交、部分撤单和 DEAL 查询对账均有测试。

## D. 对照试验

- [ ] 对关键指标使用固定小样本逐值比较。
- [ ] 对股票池在多个换仓日比较代码、顺序和分数。
- [ ] 对交易信号比较时间、方向、目标数量/金额和原因。
- [ ] LIVE 跨日保护价缓存、最终报单前刷新缩量、资金不足废单后的减一手重试样本已覆盖。
- [ ] 在相同区间比较成交、持仓、现金、净值和回撤。
- [ ] 将差异归因到数据、时序、撮合、费用或实现。

建议阈值必须由用户或策略性质决定。不要自行用“收益接近”代替信号级一致。

## 无 QMT 环境时

将以下项目明确标为“未运行”：

- QMT API 运行；
- 本地数据完整性；
- QMT 回测；
- 券商权限/枚举可用性；
- 模拟柜台和实盘行为。

同时提供精确的客户端操作、下载品种/周期、回测参数和预期日志检查点。
